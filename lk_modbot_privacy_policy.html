Privacy Policy — LK-ModBot

Last updated: 20th September 2026  |  Effective date: 20th September 2026

This policy explains what data LK-ModBot ("the Bot") accesses, what it stores, and how it's used. The Bot is operated by Legend Killer ("the Operator") and is installed only in Discord servers the Operator personally manage. It is NOT a publicly-listed bot available for any/every servers to add and the Operator is the sole user that can administrate the bot.

1. What the Bot does

LK-ModBot provides moderation and utility features for the specific servers it's installed in, including:

  • Moderation commands (kick, ban, unban, timeout, member lookup)
  • An automated moderation log (message edits/deletions, joins/leaves, bans/kicks/timeouts, nickname and role changes, permission changes)
  • A configurable blocked-word/regex content filter
  • Detection of self-reported underage users in a single designated channel, to help enforce Discord's own 13+ age requirement
  • A passive, read-only server security/permissions audit for the Operator
  • Attachment-spam detection with automatic banning
  • Sticky channel messages, reminders, and live-stream / service-status notifications
  • A web dashboard where server the Operator configure the above, per server

2. Data the Bot processes

Message content

The Bot reads message content in real time, within servers it's installed in, to power the features above (the blocked-word filter, the underage-detection scan, the moderation log's display of edited/deleted content, and generating a reply when the Bot is @mentioned). Message content is not stored in any/the Bot's database.

One exception: when the Operator runs the /remind command, the reminder text they provide as a command argument is stored locally in a private server until it's delivered back to them, then deleted. This is a feature the Operator actively invokes (not passive scanning) and is limited to that one command.

Member and server data

The Bot accesses member information (usernames, display names, user IDs, roles) to power moderation commands, the security audit and join/leave/update logging. This data is used transiently/in the moment a command runs or an event fires. Member profile data is not written to the Bot's database.

Configuration data (what is actually stored)

The only data persisted in the Bot's local database is the Operator-provided configuration, scoped per server:

StoredPurpose
Channel IDs/role IDsWhich channels/roles a feature applies to (e.g. the mod-log channel, ignored roles)
Blocked word/regex listOperator-entered moderation rules
Sticky message textOperator-entered channel messages
Streamer/channel usernamesOperator-entered, for live-notification features (public usernames only)
Reminder textOperator-entered via /remind, deleted after delivery
Feature toggles/thresholdsOperator-configured settings (e.g. spam sensitivity, minimum age)

This data is stored in a local database on the Operator's own infrastructure. It is not sold, shared with third parties, or used for advertising.

3. Data we do NOT collect or do

  • We do not sell or share user data with third parties.
  • We do not use message content or member data to train machine learning or AI models.
  • We do not track users across servers or build cross-server profiles.
  • We do not access data in servers the Bot has not been added to.
  • We do not collect Presence data (online/offline status, activity) — the Bot does not request this intent.

4. Third-party services

For specific opt-in features, the Bot makes outbound requests to these services' own public APIs. No private user or message data is sent to them — only the public usernames/channel identifiers the Operator configures:

  • Twitch, Kick, YouTube, TikTok — to check whether a configured public account is currently live, or has posted a new video
  • discordstatus.com, status.twitch.com — official public status-page APIs, to relay service incident updates

5. Data retention

Configuration data (Section 2) is retained until the Operator removes it via the dashboard or removes the Bot from their server, at which point it can be deleted on request (see Section 7). Message content and member data are not retained beyond the moment they're processed, except the one /remind exception noted above.

6. Privileged intents

The Bot requests two of Discord's three privileged Gateway Intents:

  • Message Content Intent — required for the blocked-word filter, underage-detection scan, mod-log content display, and @mention replies.
  • Server Members Intent — required for member lookup commands, the security audit, and join/leave/update logging.

The Bot does not request the Presence Intent.

7. Your rights and choices

Because the Bot is operated per-server by the Operator:

  • The Operator control which features are enabled and can disable or reconfigure any feature, or remove the Bot entirely, at any time via the dashboard or by removing it from Discord.
  • To request access to, or deletion of, configuration data associated with your server, contact Legend Killer.
  • Individual members who want a channel or role exempted from moderation-log or filter scanning should ask the Operator to add it to that feature's ignore list.

8. Children's privacy

Discord requires all users to be 13 or older. The Bot includes an opt-in feature specifically to help the Operator identify and act on self-reported underage users in accordance with Discord's Terms of Service, in a single designated channel. The Bot does not knowingly collect data from users it identifies as under 13 beyond what's needed to action that enforcement (timeout and report to moderators).

9. Changes to this policy

This policy may be updated from time to time. Material changes will be reflected by updating the "Last updated" date at the top of this page.
